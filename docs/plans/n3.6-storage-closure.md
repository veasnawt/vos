## Observation design verified before coding

Authoritative ownership already lives in process/thread tables, file sessions and
embedded nodes, ext2 readers, block cache/device records, driver slots/descriptors,
and io_scope tickets. Existing counts and audits are reused. No ownership table
will be introduced as runtime authority.

A kernel-private storage_observe.h schema and VOS_TEST-only readers copy:
- Process record identity, PID, state, root, TID, kernel-stack top and page count.
- Thread record identity, non-reused TID, process identity, state, saved stack
  pointer, stack bounds/slot, actual stack owner, queue identity and next waiter.
- File volume identity/generation/device/incarnation/epoch/reset sequence,
  references, active/setup ownership; all session PID/TID identities, grants,
  published nodes and reservations (token, inode, rights, generation, kind).
- Reader identity, device/epoch, busy/dead state, waiter head/tail identities.
- Registered block identities/incarnations and cache-frame identities, line
  states/keys/pins; loading-queue head/tail identities and existing counters.
- Driver state/mode, six pool frames and quarantine flag, request slot identity,
  live owner TID, ticket, inflight/done/abandoned flags and waiters, fixed
  explicit descriptor-table availability and contents, driver-maintained ring indexes
  and lifecycle counters. Pool allocation alone does not establish table availability;
  absent/uninitialized tables produce zero descriptor records while pool accounting
  and request identities/counters remain observable.
- Ticket identity, scalar owner PID, live TID/scope identity, request/debt flags,
  guard presence, remaining budgets and deadline.

Snapshots run only in thread context with IF=0. No helper allocates, waits, yields,
logs, reads PCI configuration or device registers, submits I/O, collects completions,
checks a mutating scope guard, resets, or cleans state. Driver-maintained state and
CPU-owned descriptors are observed; asynchronous device-written used-ring fields
are excluded from equality checks. Every snapshot is zero-initialized.
All capacities and observation storage have compile-time bounds.

Process pages/root and allocator bitmaps are inspected through their existing
read-only views. A fixed baseline allocation bitmap provides exact set comparison
at quiescence, alongside allocator recount and explicit cache/DMA frame identity
checks. Active snapshots establish observable ownership relationships, not a
universal frame-provenance proof. Arbitrary kernel allocations cannot be assigned
an invented owner. Observer equality without intervening execution tests that
observation does not change authoritative CPU state.

## Stage 2 lifecycle oracles

ACTIVE: exactly one expected caller process and controller, and exactly one caller
thread must be present. Match process record/PID/root/TID and stable thread record/
TID/process/stack-owner identities against trusted process state and the pre-read
snapshot anchor; reject missing/duplicate or stale identities. Expected identities
are refreshed for each legitimate new process/thread incarnation.
Expected live session/scope, reader and loading line remain
charged; real transport request has matching owner and ticket. A RAM error-injection
backend has no hardware descriptor and must not be reported as DMA pending.

DETACHED (BIOS IRQ smoke only): the killed process and its thread/session/pages
are gone; an explicitly identified abandoned slot retains only scalar ticket debt
and the existing DMA pool. No scope, callback, process, thread or caller-buffer
pointer survives detachment. Retirement must occur through existing deferred service,
without another userspace file syscall or collection by the observer.

QUIESCENT: no smoke-owned process, thread, session, node, reservation, grant, waiter,
request, abandonment or ticket remains. The configured reader, registered devices,
32 cache frames and six DMA frames are declared persistent baseline resources.
Stable baseline thread records/TIDs/processes/stack slots/bounds/owners must match,
not merely their count. Saved RSP, scheduling state and queue links may legitimately
change. Predicates inspect recorded addresses only as scalar identities.
Cache contents and monotonic IDs/counters need not rewind. Exact allocated-frame
bitmap equality and all applicable existing quiescent audits are required.

FULLY STOPPED and QUARANTINED execution coverage is deferred: the three authorized
smokes do not require a new reset-refusal injection or global driver shutdown.
The schema reports retained pool/quarantine explicitly, never as freed frames.
A genuine retained quarantine cannot satisfy the ordinary reclaimed baseline.

## Exactly three smoke scenarios

SMOKE-01: existing ABI v2 reader, known dup/x/name.txt bytes, real read-only virtio
transport. Existing channel barrier plus skip-notify establishes an IRQ wait or
poll-yield point. Snapshot before/during/after; existing notify releases the request.
The unchanged reader verifies exact bytes/length; process exit and destroy reclaim
its resources.

SMOKE-02: existing RAM-backed immutable fixture and established BLK_EIO injection
pattern from selftest_file.c. A bounded backend gate establishes an actual read
inside ext2/block handling before media-error return and sector fallback. Existing
error.elf checks all 4096 destination bytes unchanged and exits with exact EIO.
Clear injection; an ordinary reader must then succeed. Both firmware types apply.
This is a modeled backend/media error, not a claim of physical device failure.

SMOKE-03: existing real-driver wait/poll-yield barrier, proc_kill and unwind.
BIOS: require DETACHED debt after process destruction, then existing notify plus
scheduler/idle retirement without another file call. UEFI polling: kill is remembered
until the finite inner wait ends; no interruptible-wait/orphan claim. Require killed
read syscall, no user return, no logical debt; detach the reader and use supported
reinitialization to restore driver READY after a polling timeout. This smoke does
not remount or perform a subsequent file read after that reinitialization.

Corrective validation adds a synthetic missing-table input filter to the real
storage_observe path, while keeping the real queue, pool and device unchanged.
It verifies retained allocated frames, explicitly unavailable/zero descriptors,
unchanged request accounting and observation before/after restoring the filter.
This proves the partial-initialization guard, not live quarantine lifecycle closure.
Altered snapshot copies must fail for missing/duplicate caller threads, wrong
process PID/record, wrong stack owner, stale TID and equal-count baseline identity/
ownership mismatches. Authoritative ownership structures are never corrupted.

No existing fixture, syscall, production behavior, security assertion, mutation
definition, work/poll bound, pool or thread capacity changes.

## Pilot and stop boundaries

One make job, one QEMU, at most 30 minutes and 256 MiB aggregate newly allocated
storage including temporary outputs, source snapshots, logs and evidence. C: reserve:
10 GiB plus remaining admitted allocation plus 256 MiB safety margin. Linux reserve:
1 GiB. Fail closed when measurements/dependencies are unavailable.

Use only explicit small artifact copies with GNU cp --sparse=always --reflink=never;
never copy whole build or sparse fixture-source trees. Preserve all prior evidence
and secondary worktrees. The future 2 GiB campaign is not authorized.

Host storage safeguards never reduce VOS features, correctness, security, test
assertions, required configurations or necessary evidence. If capacity is insufficient,
stop, preserve state and request separately approved capacity with a conservative
estimate; do not delete evidence or move/resize/compact the VHDX automatically.

Existing three-smoke assertions plus focused unchanged file regressions, production
loaded-byte equivalence/reproducibility, frozen hashes and footprint checks form
this pilot. Full historical matrix, five mutations, stress implementation and stack
instrumentation belong to later separately authorized stages.

The focused pilot is implemented and verified; [Stage 2 evidence](../results/n3.6-stage2.md)
records actual commands, the initial image-registration failure and correction,
firmware applicability, footprint and limitations. This is ready for human review,
not milestone completion. No commit or Stage 3 is authorized.
