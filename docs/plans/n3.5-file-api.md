## 1. Goal and boundaries

Allow separately built ABI v2 programs to read regular files and enumerate directories
on one trusted, read-only ext2 volume, solely through directory/file capabilities supplied
by trusted startup configuration. Reuse ext2, block I/O, driver buffers, scheduler waits,
process teardown, ELF notes and validated user copies.

The implementation is a thin file-slot/node layer, not a general VFS. No heap, inode cache,
mount namespace framework, filesystem switch, filesystem service, new scheduler model,
driver replacement or new interrupt controller is proposed. No writes, raw disk access,
user-selected mounts, user process creation, handle transfer, symlink following, libc,
shell or physical-machine testing belongs to N3.5. Existing boot-module execution stays
in place; this milestone reads program data, not executable images from disk.

N3.6 remains a later closure milestone. The adversarial concurrency and cleanup tests
required for safely exposing files are acceptance requirements of N3.5, not deferred to
that closure.

## 3. ABI decisions submitted for approval

The companion ABI document specifies registers, layouts, error precedence and examples
of zero-length/EOF behavior. The proposed additions are:

| Number | Contract |
|---|---|
| 5, reused | Close an owned channel as today; for v2, also close an owned file/directory without I/O |
| 6 | `file_open_at(dir, path, path_len, rights)` -> new token |
| 7 | `file_read_at(file, dst, len, offset)` -> bytes, 0 at EOF |
| 8 | `file_stat(handle, dst, 64)` -> 0, fixed 64-byte metadata |
| 9 | `directory_next(dir, cookie, dst, 272)` -> 1 entry or 0 at end |
| 10 | `file_initial(index)` -> existing startup grant token (index 0 or 1) |

Existing numbers 0–5 and errors 1–9 are unchanged. New errors 10–20 are defined only in
the v2 proposal. ABI v0/v1 return ENOSYS for every new call before examining arguments.
V2 inherits all v0/v1 execution contracts. The new runtime supplies `abi_note_v2.S` and
`syscall_v2.S`, reusing unchanged `crt0.S` and existing syscall stubs where appropriate.
No default conversion of old applications or IPC fixtures to ABI v2 is proposed.

Positional reads and caller-supplied enumeration cookies remove mutable open-file
offsets, seek calls and per-file cursor locks. The bounded entire read is committed with
one copy; errors never expose a partial prefix. Readdir returns one complete record or
nothing, and stat zeroes all reserved bytes. This is intentionally smaller than POSIX.

## 4. Namespace and security model

### 4.1 Trusted provisioning

One kernel-owned volume record binds an explicitly chosen `blk_id_t` and its epoch to
one private `ext2_fs`. It is not selected by filesystem labels, arbitrary PCI enumeration
order, an untrusted executable name or a userspace path. In N3.5's test launchers it is the
explicitly registered fixture device or the already validated selected virtio disk.
Normal production hello needs no disk and must keep booting if storage is absent.

Each selected v2 launch can have 0–2 trusted grant descriptors: grant index, trusted
directory location and maximum rights. The launcher validates the volume and directory
and installs file tokens before `proc_start`; the new file_initial call only discovers
those already-installed tokens. Resolve trusted setup paths under the same work budget,
preferably using the same component walker. Missing mandatory grants fail setup with a
trusted diagnostic and complete rollback, rather than widening authority or silently
substituting the volume root. A launch requiring no grant can still run with none.

Example: launch A receives index 0 for an application fixture subtree with all four
read-only rights; B receives index 0 for a different subtree. Numeric index 0 is a role
in each launch configuration, not a path to a global `/applications` tree. Index 1 may
grant a second explicitly selected subtree. The provisional D-S7 layout stays a policy
convention, not kernel hard-coded authority. No initial grant or derived directory may
name volume-root inode 2.

### 4.2 Enforcement and threat boundary

Each file slot records token, owner identity, volume generation, inode, kind and rights.
All file calls resolve tokens only in the caller's side table. Rights READ/STAT/ENUMERATE/
TRAVERSE are inherited by intersection with the requested subset; there is no elevation,
superuser check, owner-mode bypass or user-controlled grant operation. ENUMERATE reveals
names/types, not handles. Closing a directory does not revoke its already-derived files.
There is no process handle transfer or duplication API; open_at on `.` can narrow rights.

Absolute paths, every `..`, symlinks at any position and root-inode child aliases are
refused. `.` is handled lexically. Single-component ext2_lookup/stat supplies the only
walk step. The full private path is checked before lookup, including embedded NUL,
separator, length, component and depth rules. D-S5 is proposed as case-sensitive exact
bytes; D-S6 is explicitly **no normalization**, including no UTF-8 validity requirement.
The ABI document states how this differs from storage.md's earlier UTF-8 suggestion.

The disk remains untrusted for parser bounds, memory safety and error handling. Namespace
authorization additionally assumes that trusted provisioning selected the intended,
immutable image/subtree. Neither ext2 nor a directory handle authenticates the media:
a hostile disk can forge a child entry to another inode or make a file's blocks alias
another file. Rejecting `..` does not prove a corrupt directory graph represents the
intended host tree. Hard links within the supplied graph are aliases, not new authority
derived from a global inode API. Tests must cover malicious directory cycles and root
aliases, but cannot establish authenticity. N3.5 therefore permits only trusted provisioned
images; arbitrary removable-media namespaces and cryptographic authentication require
a later design. This limitation must remain explicit in status at implementation closure.

File tokens use `0x4000000000000000 | serial`, serial 1..`0x3FFFFFFFFFFFFFFF`, never reused
within a boot. Match both token and caller identity; stop on counter exhaustion. Another
process's file token cannot numerically alias a local live file token. Tests must also
keep the separate v1 rule: equal channel values in different processes may validly name
their respective local endpoints; they never name the other process's endpoint. No
claim of random, unguessable capability values is made.

## 5. Thin node layer and ownership

Proposed internal module `file.{h,c}` owns fixed tables, lookup policy, ABI record assembly
and file auditing. A node descriptor is embedded directly in a file slot; no global inode
cache, filesystem operations table, pathname cache, per-open reader or generic VFS exists.
Two handles for an inode are independent descriptions with no shared position.

Use a static side table for at most PROC_TABLE=8 sessions, keyed by process pointer and
non-reused PID. It avoids growing `struct process`, which also appears in sizable existing
test arrays. Register a session at first trusted v2 setup (or first v2 file call with no
grants); only a registered live process may acquire one. Old ABI processes get no session.
The existing eight channel slots are untouched; a session has eight additional file slots.
No user API leaks the side-table slot index or a pointer.

| Resource | Owner | Lifetime |
|---|---|---|
| Configured reader and volume record | Trusted volume setup | Attach through explicit teardown; may persist as accounted boot state with zero user handles |
| File slot / embedded node | One process session | Successful open/provision until close, process end or failed setup rollback |
| Volume handle/operation references | File layer | One per live file and active operation; no destruction while nonzero |
| Path snapshot and 4 KiB bounce area | One process session | Only its single active syscall uses them; cleared before reuse/release |
| Operation context and admission ticket | Calling thread / bounded scope module | Enter to unwind; an abandoned device request retains a scalar ticket debt afterward |
| Cache frames | Existing block layer | Existing registered-device lifetime; no new user pins |
| DMA frames and abandoned buffers | Existing driver | Until validated completion or confirmed reset; quarantine on unconfirmed reset |

Reserve a free file slot before an open starts I/O, publish it only after the final checks,
and release every reservation on failure. File-close is nonblocking and releases a handle
reference, not the shared reader. Last-reference close does not trigger disk work. Trusted
volume teardown closes the reader only with no active operation, waiter or user reference;
then the existing block/driver teardown can run. The persistent configured reader is an
explicit baseline resource, not a leaked per-process reader.

Keep v1 `channel.c` and its exported handle_close/handles_close_all implementations intact.
For syscall 5, add dispatch at syscall.c. In process.c add file_close_all alongside existing
channel cleanup in terminate and destroy, including processes that never started. Extend
proc_audit with a separate file audit call rather than treating file nodes as endpoints.

## 6. Bounded concurrency and cancellation

### 6.1 Scope and admission

Expose disk work synchronously to the one calling process thread. Other processes can
run while it waits. A shared reader serializes individual ext2 operations; no guarantee
of simultaneous device submissions or speedup is made. Each caller has private path,
output and cookie state, so interleaving lookup/stat/read operations is safe on a bound
read-only image. Reader busy transitions and wait registration stay atomic under IF=0.
Recheck the volume epoch after any wait and before success; metadata from different
bindings may never be combined or copied out.

Use a small optional `io_scope.{h,c}` rather than adding parameters to every old kernel
interface. I1 realizes per-thread lookup in the two-ticket table, rather than a separate
THREAD_MAX table: a ticket records trusted owner PID, current thread ID and the live
caller's scope pointer. The caller-owned scope holds the absolute deadline, remaining
logical/backend/wait counts, persistent outcome and scalar ticket ID. This preserves
the same admission contract with less static storage. Old kernel clients have no scope
and keep their existing limits, error behavior and test expectations. No global current-scope pointer is safe across a context switch.

Admission has **two global tickets**, counting both active calls and detached abandoned
requests. Each PID may hold only one ticket, including a detached debt. No free ticket
means EAGAIN without sleeping; a caller with an unretired abandoned request also gets
EAGAIN. Two callers can therefore make logical progress concurrently without using all
four driver request slots. This is a capacity guarantee, not starvation-free scheduling.

Every admitted call has an absolute 200-tick deadline (nominally 2 s at 100 Hz), at most
512 ext2 device-access steps **including cache hits**, and at most 256 backend read
submissions **including sector-by-sector error fallback**. Existing smaller loop/request
bounds still apply. Check the scope before and after each ext2 device access, at API
entry, between path components, before each backend submission and before/after a wait.
Work exhaustion returns EAGAIN without committing output; it never restarts the budget
inside the same syscall. Large cold lookups may hit this limit: see risks.

Reader and block-cache waits use the earlier of the active scope deadline and any local
deadline, keep existing 1024 retry caps, and check persistent kill_reason before requeue.
No scoped wait may pass deadline 0. A cache/reader waiter releases no state owned by the
thread doing the actual load. No lock is held while waiting for a ticket (admission is
nonblocking), and no user-controlled directory object has its own long-held lock.

### 6.2 BIOS IRQ mode

Clamp a scoped driver wait to `min(request deadline, operation deadline)`, retaining the
existing 10-tick completion recheck and 200-tick request limit. Expiration resets/fails
the outstanding transport request as today; the scope records TIMEOUT before ext2 maps
the layer result to generic EIO. Kill/cancellation uses the existing abandon path, with
exact slot/ticket bookkeeping. Do not reset the device simply to kill one waiter when
abandonment can preserve another caller's request.

### 6.3 UEFI polling and mode transitions

Do not add IOAPIC, MSI, MSI-X or kernel preemption. Keep the existing poll-count limit
(50,000,000 per request), cooperative yield every 4096 polls, and tick checks. A kill
while polling cannot assume thread_interrupt ends the inner wait: polling currently
does not wait on a queue. Remember kill_reason and unwind at the next safe return from
that bounded driver operation; do not start another metadata access or copy out afterward.
Scope deadline checks at yields may shorten a wait, but **immediate polling cancellation
is not promised**. BIOS storm fallback follows the same rules if IRQ mode becomes polling.

PIT ticks can be lost or fail to advance while IF=0 kernel code keeps running. The deadline
is a scheduler-tick bound, not a hard wall-clock guarantee. Independent poll, metadata,
submission and retry counts supply finite work bounds when ticks cannot advance. Host
stalls and a non-yielding unrelated kernel client cannot be given a real-time bound without
redesigning the kernel; no such claim is part of N3.5. Tests distinguish this from hangs.

### 6.4 Process kill and driver-owned buffers

1. proc_kill sets kill_reason and wakes a queued owner through thread_interrupt, as today.
2. A scoped reader/cache waiter notices kill before requeue and exits. An IRQ device waiter
   abandons its own slot; a polling waiter finishes/fails at its safe bound before unwinding.
3. The block layer clears a failed loading line and wakes its waiters; ext2 clears busy and
   wakes reader waiters. The file call drops reservations/references and its scope pointer.
4. No user copy or handle publication occurs after kill was observed. Existing
   proc_user_trap sees kill_reason after syscall_dispatch and terminates without IRET to
   user mode. A nonfatal kernel interruption with no kill_reason returns EINTR instead.
5. Close file handles and channels only after the file call has unwound. After leaving the
   address space, exit/reap the thread; proc_destroy may then free user pages and the session.
   Check active context/reservations are zero before freeing them. Cleanup is idempotent
   for exit, user fault, kill, failed setup, failed start and destroy.

DMA never targets user pages, file slots or session bounce buffers. The driver owns its
six pool frames and only copies validated completed data into a live caller's kernel
buffer. On abandonment, no late path retains a caller destination or process pointer.
Associate the slot with a scalar ticket serial. If the call detaches with an abandoned
request, keep that ticket charged until completion/reset even if the process and session
have been destroyed. Retirement releases only that scalar debt once. A replacement process
has a new PID; the old debt can neither address it nor be rebound to its file state.

Add a small driver collector service callable in existing scheduler/idle **thread-context**
maintenance, including timer wakes with no device IRQ pending. With abandoned slots present
it reaps completions and enforces the existing 200-tick abandonment reset bound; it must
not require the next file syscall to run. Hook both the ring-3 scheduler tick and idle
deferred-maintenance path. No worker thread/stack, new IRQ path or scheduler policy is
needed. Test the final-process-killed/no-further-I/O case explicitly. Confirmed reset
retires debt; unconfirmed reset disables bus mastering and keeps the existing bounded DMA
quarantine. Never free/reuse uncertain DMA frames or repeatedly allocate replacement pools.

### 6.5 Device failures and epoch binding

| Event | Current call | Later operations on the same binding |
|---|---|---|
| EOF / sparse hole | Short/zero count / zeros; ordinary success | Usable |
| Recoverable media read error; device remains ready | EIO; discard any private prefix | May retry; no automatic syscall-level retry |
| Corrupt metadata | EIO; no output/handle publication | No panic; a different unaffected object may still be usable |
| Unsupported ext2 feature/target | EUNSUPP | No fallback interpretation |
| Busy admission or bounded work exhaustion | EAGAIN; no output | May retry; large cold walks may still exceed budget |
| Operation or transport timeout | ETIMEDOUT for the initiating scoped call; safe unwind/reset as needed | Binding is invalidated if transport reset/loss of availability made its identity uncertain; ESTALE thereafter |
| Temporary unavailable state, no known reset or generation change | EUNAVAIL | Recheck on next operation; no cached-data bypass |
| Reset, removal, reinitialization, block ID/epoch change | ESTALE unless this call's own recorded timeout takes precedence | Permanently ESTALE for nonzero file operations until close; never silently rebound |
| Other caller's reset while waiting | ESTALE, or EUNAVAIL until the reset is identified | Mark binding dead when reset/change is known |
| Kill | No user return | Process resources released after unwind; driver debt retires separately |
| Nonfatal interruption | EINTR, no user output | Same live handle may be retried after its ticket debt retires |

The file layer stores an additional never-reused volume generation and checks the block
ID/epoch plus transport reset invalidation. Expose a narrow invalidation notification if
the current block epoch changes only at reinitialization: even cached file calls must
not succeed after a known reset. The reset initiator records the reason in its scope;
other callers observe the dead binding. ext2's shared diagnostic string is never the
error channel. Deadline expiration while queued, with no request submitted, does not
reset the device or invalidate a healthy volume.

A stale handle remains a live owned handle: close succeeds, and file_initial can discover
it, but I/O/stat/enumeration/open return ESTALE (zero-length reads follow the ABI exception).
Remount/regrant is trusted setup only, after all references, active calls and abandoned
requests for the old binding have drained. No API upgrades a stale handle to new media.

## 7. Proposed limits and memory budget

| Limit | Proposed bound / rationale |
|---|---|
| User-visible configured volumes | 1 ext2 volume; at most one of the existing four reader slots |
| Sessions | 8, bounded by PROC_TABLE |
| File/directory slots | 8 per process, including up to 2 initial grants; 64 total |
| Existing channel slots | 8 per process, unchanged; combined maximum 16 handles/process |
| Node descriptors | Embedded in file slots; <=64 bytes each, <=4096 bytes total |
| Read staging | One 4096-byte kernel buffer/session; 32 KiB total |
| Path snapshots | 1025 bytes/session (1024 + private terminator); 8200 bytes total |
| Metadata/dirent staging | Reuse that session's bounce area; no extra 4 KiB allocation |
| Other session accounting | <=256 bytes/session; <=2048 bytes total |
| Volume, ticket and thread-scope tables | <=4096 bytes total, including alignment allowance |
| All new production static storage | **<=64 KiB**, verified by size assertions/map accounting; table components above total 51,208 bytes (<51 KiB) before final padding |
| New production code + rodata | Initial review allowance <=64 KiB; measure, not a promised result |
| Total production image growth | Initial ceiling <=128 KiB, including all new code/static state; retain linker and runtime 4 MiB guards |
| Additional N3.5 test-only image growth | Initial ceiling <=128 KiB beyond production additions; measure the largest complete test image |
| Additional PMM frames | 0 in the proposed production file layer; existing 32 cache + 6 DMA frames remain 152 KiB |
| Extra kernel threads / stacks | 0 |
| Active operation | 1 per process; 2 globally including abandoned ticket debts |
| Backend requests | Synchronous, <=1 in flight/operation; <=2 user-caused slots including abandoned requests; driver remains at 4 slots |
| Cache holds | No user pins; at most one loading line per active synchronous call, <=2 total from file callers |
| Work per syscall | 512 ext2 device accesses (hits count); 256 backend reads (fallback counts); 200-tick total deadline; old local bounds still apply |
| Paths | 1024 bytes, 255/component, 64 components |
| Syscall output | <=4096 bytes read; exactly 64-byte stat or 272-byte directory record |

Per-process tables partition all file-node capacity: one process cannot allocate another's
slots. Admission limits prevent one PID, including a cancelled operation, from consuming
all driver slots or cache lines in LOADING state. Cached VALID lines remain a shared LRU:
one process can churn performance, but cannot pin or reserve all lines. There is no claim
of cache residency quotas, guaranteed latency or fairness against repeated call loops.

Measured during the preceding clean assessment at this exact base:

| Image | `__kernel_phys_end` | Room to `0x400000` |
|---|---|---|
| Production x86_64 | `0x1a4000` | 2416 KiB |
| Base self-test x86_64 | `0x238000` | 1824 KiB |

These are symbol readings from the fresh binaries in section 2.1, not estimates based on
older N3 checkpoints. Largest ext2/fault/combined images must be measured afresh before
implementation closure. Reject growth past the agreed allowances or return for review;
do not raise the linker limit, remove guard pages or quietly expand process/thread pools.
Keep new large buffers off the 16 KiB kernel stacks; inspect compiler stack-usage reports
for the deepest file -> ext2 -> block -> driver call chain.

## 9. Detailed acceptance test matrix (PROPOSED, NOT RUN)

Tests use separately built real user ELF programs plus trusted kernel orchestration and
fault injection. Match trusted kernel markers, expected exit status and state audits;
never trust verdict strings printed by a user program. Host timeouts are failures, never
successes. Use explicit NOT APPLICABLE with a reason for unavailable hardware behavior.

## 12. Decisions and unresolved risks for review

1. **ABI shape:** approve syscall 10 for fixed-index startup discovery, reuse close 5,
   explicit positional reads, single-entry cookies and exact fixed wire sizes.
2. **Compatibility:** append errors 10–20; preserve all old semantics and binaries while
   accepting note 2. V1 handle generation wrap remains a documented legacy limit.
3. **Authority/names:** approve two non-root grants, separate eight-slot file table,
   inherited rights, no `..` at all, no final-symlink metadata handle, exact byte names
   with no normalization/UTF-8 validation (D-S5/D-S6). This is intentionally stricter
   traversal and broader byte naming than some older proposal language.
4. **Media trust:** a directory grant is not a signature of a disk tree. A malicious disk
   can alias inode/block contents. The design assumes a trusted provisioned immutable
   namespace and protects parser memory safety independently; authentication is deferred.
5. **Bounded work vs availability:** 512 logical steps / 256 backend reads may reject deep
   cold walks or very large directories with EAGAIN even though the existing ext2 profile
   accepts them. Repeated identical retries need not progress. Measure representative
   fixtures in I1/I2; changing those limits requires an explicit documented design update,
   not removing the bounds or promising all 4096-block directories finish in one call.
6. **Polling latency:** an OVMF kill waits for an existing bounded inner driver operation.
   Lost PIT ticks prevent hard wall-clock guarantees. No immediate cancellation or real-time
   behavior is claimed; assert finite poll/work bounds and safe post-kill cleanup instead.
7. **Tickets and maintenance:** exactly-once scalar debt retirement, last-process orphan
   service and reset notification are the highest-risk implementation work. They must
   pass independently before user syscalls expose I/O. No late pointer may outlive a call.
8. **Serialization/fairness:** one shared reader and two tickets favor a small implementation;
   they limit concurrency. LRU cache thrash and repeated-call starvation are not eliminated.
9. **Memory/stack:** current measured headroom is adequate for proposed allowances, not
   proof of future sizes. Measure every largest test variant and nested stack usage.
10. **Device trust:** no IOMMU or hardware authentication; driver checks constrain requests,
    not a malicious DMA device. Unconfirmed reset quarantine and some failure states can
    only be tested synthetically in QEMU. No physical hardware support claim follows.
11. **Tool gate:** UEFI tools need separately authorized setup and fresh tests. The earlier
    assessment's selected BIOS checks do not replace the full baseline or new API matrix.

### 13.1 Ownership at each operation state

| State | References/ownership and permitted transition |
|---|---|
| Not admitted / queued for capacity | No request or retained pointer; admission returns EAGAIN rather than queuing |
| Running | Thread owns a live scope; one of two tickets is charged; <=1 driver request is attached |
| Blocked on reader/cache | Scope remains on the caller's live kernel stack/private state; waiter is on one queue with a finite deadline; no destination pointer retained by storage |
| Blocked on device | Driver owns DMA frames; slot records live thread and scalar ticket; caller pages/staging stay alive |
| Interrupted | Set a persistent scope stop reason; unlink a waiter, unwind layer state; never requeue after cancellation |
| Abandoned | Slot loses thread owner; only driver frames and scalar ticket debt remain; no scope/process/caller-buffer pointer survives detachment |
| Completing | Validate completion, then release the ticket's request reference exactly once; abandoned bytes are discarded |
| Retired | Slot/debt released after completion or reset; last reference clears ticket; scope may be ended/destroyed only after it owns no live non-abandoned request |

Thread exit with an active scope is an invariant failure. Ending a scope with a live
non-abandoned request is also an invariant failure. Tests use kernel caller threads for
the new internal operations because no user file entry point exists in Stage 1; existing
process/IPC kill regression must still pass. Actual user kills during file syscalls belong
to the later API stage and must not be reported as already tested.

### 13.2 Finite waits and reset observability

Scoped waits combine the 200-tick absolute deadline with finite metadata/backend budgets,
existing 1024 reader/cache retry caps, and a total scoped queue-wait count capped at 1024.
The driver keeps the independent poll cap in every polling/fallback path, clamped to
50,000,000 even if a test override is larger. IRQ-to-poll fallback inherits the earlier
operation/request deadline; it must not extend either. Tick expiration with no submitted
request must not reset a healthy device. A timeout of an in-flight request uses existing
safe reset ordering. No promise is made if unrelated trusted kernel code never yields
or the host itself stops running.

Expose reset observability additively in the block descriptor (a reset sequence), without
changing the existing epoch's meaning or the old ext2 error mapping. Increment it when a
known driver reset invalidates the binding, before waking waiters. A future file volume
compares ID, epoch and this sequence. Scope-local reasons preserve timeout/cancellation
information even through ext2's existing EIO/EINTR mapping.

Invoke abandoned-slot collection from both ring-3 and idle deferred thread-context
maintenance, even without a device IRQ or later syscall. Completed orphans retire; ones
past their existing deadline reset. Driver reset/quarantine ordering stays unchanged.
Ticket serials saturate rather than wrap; a detached ticket contains no caller pointer.

Budgets in section 7 are unchanged. Stage 1 must measure its own code/static footprint
against them and report focused IRQ/polling, frozen-tick, waiter, orphan and accounting
tests actually run. Full BIOS/UEFI claims require the corresponding full suites.

**Stop boundary:** commit verified I1 changes locally and submit the results. N3.5 remains
incomplete. I2 (Stage 2 file nodes/policy) and all userspace filesystem calls await review.
