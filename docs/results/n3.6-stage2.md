## Original pilot design and implementation

[The design](../plans/n3.6-storage-closure.md) was written before source changes.
The original pilot used a 7280-byte, kernel-private observation with fixed
capacity arrays for processes, threads/stacks, file sessions/nodes/grants,
readers, devices/cache lines, request slots/descriptors and scope tickets.
No second authoritative ownership table is introduced.

Seven append-only VOS_TEST helpers read the existing subsystem records.
storage_observe() rejects null, IRQ-context and IF=1 calls; it zeroes the output
and invokes those readers. It performs no allocation, wait, yield, callback,
scope check, cleanup, reset, completion collection or device-register access.
It excludes asynchronously DMA-written used-ring state. Helpers require trusted,
zeroed kernel output storage and the wrapper's thread-context/IF=0 contract.
No syscall or userspace ABI entry was added.

The smoke harness has three static snapshots, a 32768-byte allocator bitmap,
and two existing-format process records. That bounded subset is 64560 bytes,
with a compile-time 96 KiB guard. Snapshot objects never go on kernel stacks.
Baseline allocation data is a test oracle, not runtime allocation authority.
The whole 7280-byte snapshot compares equal across consecutive observations
without intervening scheduling; this is evidence of unchanged observed CPU
state, not a proof that observation has zero timing/cache effect.

ACTIVE checks tie the process record/PID, thread/TID/actual stack owner, session,
two published nodes, scope/ticket, reader/cache activity and real driver slot
where present. User/root frames remain allocated while the owner is pending.
Existing active-safe file/scope/process/scheduler audits also pass.

DETACHED checks require no process/session/thread ownership, with exactly one
identified abandoned driver request and scalar ticket debt; no scope/TID/guard/
slot owner survives. The full allocator bitmap already matches the persistent
cache/DMA baseline after caller destruction. Deferred retirement must release
that debt exactly once without another file syscall or observer-driven collection.

QUIESCENT checks require no smoke process/session/node/reservation/grant, waiter,
scope, ticket, live request or abandonment; the configured reader/device baseline,
32 cache frames and six DMA frames remain explicitly charged. The allocator
recount, exact allocation bitmap and cache/DMA frame identities must match.
Existing quiescent subsystem audits pass. IDs/counters/cache contents need not rewind.

Reader busy state and cache LOADING lines do not store authoritative owner TIDs.
The observer exposes those actual facts; the controlled single-operation schedule
establishes their relationship to the one active caller. This is not a general
concurrent-loader ownership proof. Active frame checks are likewise limited to
the recorded process/root/pages and DMA descriptors; no arbitrary frame owner is invented.

FULLY STOPPED and live QUARANTINED coverage is deferred. Driver pool/quarantine
state is observable, and ordinary quiescence explicitly rejects quarantine rather
than calling retained frames freed. No reset-refusal injection or global driver
shutdown was added just to exercise those states.

## Architectural review corrections and fresh verification

### Root causes and corrected invariants

1. The driver observer treated pool_ready as descriptor-table availability.
   alloc_pool sets it before bring_up initializes desc; early reset/feature/queue
   failure may retain a pool with no descriptor table. The observer now reports
   descriptors_available only for a non-null table matching the allocated ring
   frame, with consistent pool-held bookkeeping. Unavailable descriptors are
   explicitly zero. Allocated frames, quarantine flag, request identities and
   counters are still reported. Availability is not active-request ownership.
   No production initialization, reset, release or completion path changed.
2. ACTIVE checked a caller thread only if one was found; QUIESCENT checked thread
   counts alone. Pure snapshot predicates now require exactly one expected caller
   process, controller and caller thread, matching process PID/record/root/TID/
   stack/page/state fields and stable thread record/TID/process/stack identity.
   A mandatory pre-read snapshot anchors the caller thread for each fresh
   incarnation. QUIESCENT compares baseline pool-slot identities, TIDs, process
   bindings, stack slots/bounds and actual owners, while allowing RSP, scheduling
   state and queue links to change. Snapshot addresses are compared as scalars,
   never dereferenced by these predicates. Original count checks remain.
