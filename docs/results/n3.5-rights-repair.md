# N3.5 prerequisite: full-width rights validation

Base: `2f51d98`; isolated branch `fix/n3.5-rights-width`. Stage 3 remains
uncommitted until separately verified. No main change, push or merge to main.

The original Stage 2 `file_open_at` accepted a 64-bit rights argument but used
32-bit unsigned complements. Bits 32–63 escaped validation and were truncated
at publication. The isolated original reproduction accepted bit 32, bit 63 and
READ|bit32; three added assertions failed while the original 201 passed. No
extra low-bit authority was observed. This still contradicted the approved ABI.

The valid mask is now explicitly `UINT64_C(15)`; attenuation complements widen
the stored parent rights before inversion. Trusted grant input rights are also
64-bit, checked for all descriptors before reserving a session. Publication
accepts the full-width validated value, asserts its invariant and only then
stores compact node rights. Valid rights, node sizes, tokens and channels are
unchanged. No new static buffer, pool, syscall or writable operation.

The focused matrix checks each undefined bit 4–63 alone, with READ, and with all
valid rights. Invalid opens and trusted grants leave backend-read counts,
handles, sessions, grant discovery, token issuance and audits unchanged. All
16 valid masks and all 256 parent/child combinations exercise attenuation.
The existing ownership, stale-token, channel confusion and wrap tests remain.

The complement/narrowing audit also inspected channel creation (uint32 inputs,
kernel-private), ext2 feature masks (uint32 disk fields), CPU/page-table masks
(64-bit constants) and VMM request flags (matching unsigned-width inputs).
No analogous full-width public-input defect was found in these paths. This is
a scoped audit, not a proof of every integer conversion in the kernel.
