## Strict parser and targeted tests

scripts/uefi_catalog.py parses physical lines independently, with ASCII space/tab
separators and CRLF support. It requires the exact complete El Torito boot-image
prefix and eight columns: entry 1, UEFI, bootable y, emulation none, hexadecimal
load segment/partition type, positive bounded sector count and LBA. The accepted
Gate A profile requires zero segment/partition fields, exactly one boot row and
one associated /efi.img path. Duplicate, contradictory, malformed or trailing
content is rejected. Numeric location/size are parsed, never universal constants.
The installed xorriso 1.5.6 -report_el_torito help output documents the columns and
is retained with the actual catalog and exact commands.

scripts/test-uefi-catalog.py reuses the original 13 inputs/expectations unchanged:
13/13 passed. In particular, NOTE-contained examples, UEFIBIOS, split physical
records and truncated entry/platform-only records all reject.
Another 24 cases passed, covering duplicate/contradictory records and associations,
missing/wrong paths, trailing fields, bootability/emulation, malformed hexadecimal,
zero/negative/oversized numbers, non-ASCII/vertical/embedded-CR separators,
valid indentation/tabs/CRLF/trailing horizontal space, and nonhardcoded relocation.
The results retain per-case names and actual/expected outcomes.

The actual test-storage-stress.py preboot path invokes this parser and independently
checks the ISO before creating writable VARS or launching QEMU. The continuation
supervisor adds storage/session checks; it does not replace guest assertions,
change the QEMU arguments or bypass validation.
