## Demonstrated defects and corrections

1. **Low severity, metadata error classification/publication boundary.** A directory
   record naming reserved inode 3 passed `ext2_readdir`, whereas lookup rejected it.
   The file layer's subsequent inode argument validation returned EINVAL instead of
   the required corruption EIO. The initial run had 829 file assertions / 1 failure;
   the isolated repeat identified mutation 7 and application exit 40. Add lookup's
   existing `entry_ino_ok` check before readdir publishes the entry. No new authority,
   partial userspace copy or resource leak was observed before the fix. All twelve
   malformed cases pass afterward, including the independent ring-3 reproduction.
2. **UEFI boot payload allocation limitation.** See the controlled matrix below.
   Neither symbol/debug stripping nor fixture reordering reliably fixes both 128 MiB
   CPU configurations. These candidate changes are **not shipped**: Makefile and
   fixture ordering retain their original behavior. The standalone diagnostic
   `check-boot-kernel.py` compares entry plus every PT_LOAD byte, address, size,
   alignment and permission flag. No GRUB/firmware code was changed.
3. **Mapping-test placement assumption.** A stripped Stage 3 payload reaches VOS at
   128 MiB, where GRUB legally places a 4 MiB module at `0x27a000`. This covers the
   entire remainder of the 2–4 MiB window. The old test falsely required a free frame
   there and used page zero when it found no unreserved mutation page (five kmap
   assertion failures). With no scratch page, the revised test requires every tail
   frame to be boot-reserved/unavailable and mapped supervisor RW/NX, and exact PMM
   recovery; it explicitly reports CPU scratch writes there as not applicable.
   Permission mutations still run on a real second-table page, requiring the exact
   boot-object diagnostic when it is reported before the generic alias diagnostic.
   The ordinary allocate/write/read/free branch remains required when space exists.
   Production PMM, page tables and verifier protections were not changed.
4. **Test-only C alignment.** The unaligned-wire probe used misaligned structure
   lvalues. Byte copies into aligned locals retain the unaligned syscall test without
   relying on undefined C alignment behavior.
