## Implementation and invariants

- `file.c/h` holds one explicitly selected ext2 reader, a volume binding and eight
  fixed sessions. Each session embeds eight 32-byte nodes, a 1025-byte private path,
  4096-byte staging area and bounded accounting. There is no heap, inode cache,
  per-handle reader, mount framework, global root handle, mutable seek position or
  additional PMM pool/thread/stack.
- Trusted `file_volume_attach(ready_process, device)` validates availability/read
  capability and the ext2 profile using that process's bounded I1 scope. Setup pins
  the process until unwind. The volume records block ID, registration incarnation, epoch, reset sequence,
  capacity and a non-reused volume generation. Known changes permanently stale the
  binding; temporary unavailability fails even cached operations but may recover.
  Detach is nonblocking and refuses live nodes, active work or outstanding I1 tickets,
  including detached DMA debt. It closes the reader only after those references drain.
- An optional I1 guard checks binding at logical/backend/wait checkpoints, including
  immediately after waits. It performs only bounded descriptor inspection, retains no
  process/session pointer and is cleared on scope end. Detached tickets still contain
  only scalar debt. Unscoped callers have no guard and retain their prior behavior.
- Trusted `file_grants_install` accepts 0–2 immutable kernel descriptors with explicit
  indices, relative setup paths and rights. Only a registered READY process that has
  not started can be provisioned; there is one provisioning per session. Validate all
  descriptors/paths, enter one scope, resolve every directory from the internal root,
  and publish all grants together. Failure rolls back the whole session. No root inode,
  regular-file or symlink grant is permitted. Discovery allocates nothing; closing an
  initial handle clears discovery and never recreates that grant.
- File tokens are `bit62 | serial`, serial 1 through `2^62-1`, bit 63 clear. The global
  issuer never decreases or reuses a serial; exhaustion returns ENOMEM. Lookup requires
  exact live token in the caller's session plus owner pointer and nonzero PID. Channel
  values remain in 1..0xFFFFFF with their unchanged legacy 16-bit generation policy.
  No token secrecy or randomness is claimed. The last-token test hook only advances
  the issuer irreversibly in test builds; it never resets the production counter.
- READ, STAT, ENUMERATE and TRAVERSE are checked independently. Opening requires a
  directory with TRAVERSE and a requested subset of its rights. Zero rights is valid;
  uid/mode grant no bypass. Closing a parent does not revoke derived nodes. Each process
  owns exactly its eight slots; full tables fail without spilling into another session.
  The 64 embedded descriptors are the node capacity, not a second global pool.
- Copy and lexically validate the complete explicit-length path before disk lookup:
  1–1024 bytes, 1–255/component, <=64 components, no NUL, absolute paths, empty or
  trailing components, or any `..`. Dots are lexical self steps. Single-component
  ext2 lookup plus inode stat refuses symlinks at every position, special targets and
  ordinary child aliases to root inode 2. Names compare exact bytes, case-sensitive,
  without UTF-8 validation, normalization or decoding. No call to `ext2_resolve` exists
  in the new layer. Cyclic hostile directory graphs cannot make a call unbounded.
- Native kernel stat/read/enumeration check rights and binding, use I1 admission/work
  bounds and commit no output on failure. Reads stage at most 4096 bytes. Zero reads
  still check own regular handle and READ, then ignore output/binding. Native metadata
  and dirent temporaries are zero-initialized; wire sizes/layouts remain Stage 3 work.
  Enumeration uses private cookies, rejects oversized/mid-record positions, skips dots,
  validates target inode/type (including UNKNOWN dirent types), and advances only on
  success; EOF leaves cookie and output unchanged.
- Sessions hold an active TID through every wait. A second operation/close/start cannot
  reuse active state. `file_close_all` cancels, wakes and defers release until unwind.
  Process destroy/termination refuses an operation that has not unwound, then closes
  files alongside channels. Real process exit, fault, kill and never-started destroy
  release sessions. Driver abandonment never retains a node/session/output pointer;
  a reaped caller may leave scalar I1 debt until independent completion/reset maintenance.
- `file_audit`, called by `proc_audit`, validates ownership, node/token uniqueness,
  initial grants, reservations, active TIDs/tickets and exact volume reference counts.
  Existing scheduler, process, ext2, block, driver and I1 audits remain in use.

## Binding rollover found during final review

The existing block ID encodes a slot plus a **28-bit wrapping generation**.
ID/epoch/reset-sequence comparisons alone could miss replacement if the numeric ID
cycled before a file operation observed removal. The first full run was stopped for
this review finding; it was not treated as a passing complete regression.

Add a monotonic 64-bit registration incarnation in the private block descriptor,
record and compare it in file volume bindings (including before/after attach), and
refuse new registrations with the existing EBUSY value before cache allocation when
its issuer saturates. Existing block ID values, generation rollover, operation
signatures and error numbers remain unchanged. No userspace ABI contract changes.
The block audit checks nonzero, unique issued incarnations. A focused test forces a
free slot to reuse an old numeric ID, with the same epoch/reset sequence, **without
an intervening file operation**; the old handle must fail ESTALE before I/O.
A shared issuer helper is checked at exhaustion without poisoning the boot's registry.
Failed grant setup also avoids repeating session release after cancellation cleanup.

## Remaining risks and Stage 3 proposal

- No cryptographic authentication of the supplied directory graph/media, IOMMU, SMP,
  new interrupt controller, physical hardware support or writable operation was added.
  Trusted configuration must select an intended immutable subtree. Parser checks and
  path restrictions cannot authenticate hostile inode/block aliases.
- Work/poll bounds ensure finite storage work, not hard wall-clock latency or fairness
  when ticks stop, unrelated trusted code does not yield, or the host stalls. Large cold
  walks may still exhaust the unchanged 512/256/1024/200-tick budgets.
- Process lifecycle tests exercise real exit/kill/fault with held files and controlled
  kernel callers cancelled during I/O. Actual user file traps, protected pointer checks,
  wire-record byte initialization and syscall/close version gates remain unimplemented.
- Native kernel read output is for trusted callers. Stage 3 must connect the existing
  session staging to one revalidated user copy before cleanup, using the still-live
  trap frame, without retaining raw user pointers or adding another 4 KiB stack/buffer.
- Unconfirmed physical reset retains the existing bounded DMA quarantine; no live
  reset-refusal device or physical hot unplug is claimed tested. Synthetic registry
  removal/epoch/reset tests are distinguished from actual QEMU device removal.
- Full fresh UEFI tooling/matrix remains outstanding. No bootloader, firmware or host
  disk settings were changed.

Recommend Stage 3: deliberate ABI note 2 acceptance, versioned syscalls 6–10, typed
close 5 dispatch, writable-range checks, fully initialized 64/272-byte wire staging and
versioned userspace fixtures. Preserve old binaries/errors/gates, use the existing
session/scope lifetime, and test invalid/protected user pointers and register state.
**Stop after the local verified Stage 2 commits; no push, merge or Stage 3 implementation.**
