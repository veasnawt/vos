# N3.5 Stage 1: bounded storage foundations

Date: 2026-10-20. Branch: `feat/n3.5-file-api`. Base: `c5f5acb`.
Documentation checkpoint: `f7b9efa`.

**Stage 1 verified locally; stopped for architectural review.** N3.5 is incomplete;
no file syscall, file handle or ABI note 2 acceptance has
been implemented. Stage 2 requires the next architectural review.

## Design decisions refined before implementation

The [ABI draft](../abi/syscall-v2.md) and [plan](../plans/n3.5-file-api.md) now explicitly
specify disjoint full-width channel/file token domains, unchanged v1 close dispatch,
serial saturation instead of wrap, prevalidated relative byte paths with no `..` or
symlink following, exact-byte case-sensitive names without Unicode normalization,
single-commit staged output, zero/EOF/overflow/pointer contracts, private validated
directory cookies, and zero initialization of all 64/272 output bytes. These remain
requirements for later stages; no passing tests of unimplemented file operations are claimed.

The operation-state table assigns ownership during admission, running, blocked,
interrupted, abandoned, completing and retired states. The 200-tick deadline explicitly
does not replace finite work, queue-wait and poll budgets when IF=0 prevents tick progress.
No resource allowance was increased.

## Implemented behavior

- Optional kernel-only `io_scope` objects use two fixed tickets, keyed by a trusted
  non-reused owner PID and the calling thread ID. Scopes survive cooperative switches
  without becoming another thread's current scope. Admission is nonblocking; nested
  scopes, a third ticket and a second ticket for an owner with active/debt work are refused.
- Each scope has a 200-tick deadline, 512 ext2 device-access steps including cache hits,
  256 block-backend reads including sector fallback, and 1024 queue waits. Stop reasons
  persist through existing layer error mappings; cancellation wins over other outcomes.
  Unscoped clients retain their original limits/interfaces. Backend budgets are enforced
  at block-layer dispatch; future file I/O must use the checked ext2/block path, not a
  raw driver bypass.
- Ext2 and block-cache followers use scope-aware waits and checks. A follower's timeout
  does not clear the other thread's busy reader/loading cache line. A failed loader still
  releases its own line/busy state and wakes followers. Existing ext2 error numbers and
  diagnostic behavior for unscoped callers remain unchanged.
- Scoped driver slots hold only a scalar ticket ID alongside the existing live thread
  owner. A ticket permits at most one live request. Completion/reset drops that request
  reference exactly once. On abandonment the thread owner is cleared; ending the scope
  clears its pointer/TID while retaining a scalar debt until completion/reset.
- IRQ waits inherit the earlier operation/request deadline. IRQ-to-poll fallback cannot
  extend it. Polling retains an independent maximum of 50,000,000 iterations (test limits
  may shorten it), even with no advancing ticks. Polling cancellation is remembered;
  the bounded inner request completes/fails safely before unwind and no stopped caller
  receives a completion copy.
- Existing process kill now also marks its matching scope interrupted before waking its
  thread. Thread exit with a live scope, or scope end with a non-abandoned live request,
  panics instead of releasing referenced memory. This stage tests new I/O using trusted
  kernel callers; actual userspace kills during file syscalls cannot yet be exercised.
- Scheduler-tick and idle thread-context maintenance collect orphaned requests without
  requiring a device interrupt or later storage call. An orphan's driver deadline keeps
  idle maintenance alive even when no thread has a sleep deadline. After it retires,
  the ordinary lost-wakeup guard remains in force.
- Block descriptors expose an additive reset sequence, updated before reset waiters
  wake. The existing epoch meaning is unchanged. Future file volumes can compare ID,
  epoch and reset sequence; no userspace stale-handle interface exists yet.
- Existing read-only descriptors, device features, DMA quarantine ordering, PMM pools,
  process layout, channel encoding, syscall numbers/errors, ELF ABI maximum, old user
  programs/runtime and `arch/i386/` are preserved.

Additional static storage is 168 B including initialized data/alignment: two tickets
(80 B), four scalar driver ticket IDs (32 B), reset sequences (32 B), issuer and alignment.
A caller-owned scope is 32 B; no production bounce/path tables are added in Stage 1.
No additional PMM pool, thread, kernel stack or device mapping is allocated. The existing
six DMA plus 32 cache frames remain the attached-storage baseline. The new reserved image
page is accounted for by the existing image reservation/PMM oracle.

The production reservation has 2412 KiB left below the unchanged 4 MiB map limit.
Both the <=64 KiB new-static and <=128 KiB production-growth allowances are preserved.
Raw production ELF file size is 540,664 -> 562,856 B (+22,192 B); that includes
debug/non-loaded sections and is distinct from the mapped reservation above.
The base self-test image is text/data/BSS 367,195/456/905,960 B (total 1,273,611 B),
versus 357,563/456/904,848 B at the baseline (+10,744 B).
The ext2 self-test variant is 394,619/456/983,784 B (total 1,378,859 B);
its reserved end is `0x254000`, still below 4 MiB. Raw self-test ELF files are
1,626,672 B (base) and 1,745,864 B (ext2). No new full nested-stack measurement was
performed; future file-layer staging/stack growth still requires measurement.

## Remaining limitations and next review

- The new scopes are opt-in, kernel-private foundations. File tokens, path enforcement,
  user copy staging, output layouts and ABI v2 negotiation remain unimplemented.
- Polling kill response can wait for the bounded inner operation. Tick deadlines are not
  real-time guarantees; independent finite work/poll counts remain necessary.
- Future userspace files must enter scopes and traverse the checked ext2/block path.
  Arbitrary trusted kernel code can still bypass that path or fail to yield; no scheduler
  preemption or universal kernel sandbox was added.
- No IOMMU, authenticated media, SMP, APIC/MSI, disk writes or physical-machine support
  was introduced. Unconfirmed-reset DMA quarantine remains a bounded existing limitation;
  no live QEMU reset-refusal behavior is claimed as tested here.
- The 512/256 limits may reject cold large lookups. Stage 2 must measure representative
  scoped workloads before exposing file calls; any budget revision needs review.
- Full UEFI verification still needs separately authorized tooling and a fresh full suite.

Proposed Stage 2 is the fixed internal file/node table, disjoint file-token issuance,
trusted non-root directory grants, component walking and rights/ownership audits with
kernel tests. It should not add new syscalls yet. **Do not start it without the next
architectural review; do not push or merge this branch.**
