## Completed capability and limits

[ABI v2](../abi/syscall-v2.md) provides trusted initial grant discovery,
handle-relative opening, bounded positional reads, file/directory metadata,
directory enumeration and safe handle closing. Handles are process-owned with
attenuated rights. Trusted startup configuration grants non-root directory
authority; ordinary programs receive no automatic filesystem grant or global root.
Reads stage at most 4096 bytes in kernel memory before validated user copies.
The existing ext2 reader remains read-only; ABI v0/v1 behavior is preserved.

This is QEMU-only verification. Physical hardware remains untested. Trusted
immutable media, one CPU/one thread per process, UEFI polling/interrupt limits,
bounded reset quarantine and finite-work timing restrictions remain applicable.
Full dynamic kernel-stack high-water proof is incomplete. Writable storage,
a shell, native desktop and networking are not provided.

## Interruption and bounded harness recovery

An unexpected WSL shutdown interrupted the final integration verification.
**The shutdown cause was not established.** Recovery separately identified a
copying defect: whole-build copying expanded multi-gigabyte sparse fixture sources
into fully allocated files. Correcting that defect does not establish why WSL stopped.

The repaired harness copies only 167 required build/dependency artifacts
(12.147 MiB logical), excluding fixture source trees and unrelated build outputs.
Regular copies use GNU `cp --sparse=always --reflink=never`; copy errors and
fully allocated results from sparse inputs are rejected. Symlinks retain their targets and FIFOs are recreated
without reading them. Controlled probes verified leading/internal/trailing holes,
all-hole files, byte contents, allocation, metadata and independent copies.
Low-space, budget, copy-failure and child-cleanup checks passed. Dependency dry-runs
confirmed no unavailable input or fixture regeneration was required.

The recovery used a 1 GiB aggregate additional-storage budget and at least 10 GiB
free on Windows C:, plus workspace admission headroom. Workspace allocation is
limited to 128 MiB; private temporary output and individual child files to 64 MiB.
Observed recovery/audit evidence allocation was approximately 167.4 MiB; sampled
monitoring is not an atomic quota or an exact instantaneous peak measurement.
Earlier logs and artifacts were preserved.

The present host guard specifically supports an Ubuntu-named WSL2 distribution
with its live virtual disk backed by C: and standard Windows PowerShell access.
That limitation belongs to this mutation runner, not to VOS itself. See
[HANDOFF's runner instructions](../HANDOFF.md#mutation-runner-current-host-restriction-and-bounds)
for host requirements, explicit selection and matching source/build inputs.
