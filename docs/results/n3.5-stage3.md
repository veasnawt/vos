## Security, copies and lifecycle

The bridge reuses native nodes, the existing private path and 4096-byte session stage.
It passes NULL native output/input pointers plus a live **kernel trap frame**, never
a user buffer to storage. User addresses are decoded at the copy boundaries; none is
stored in a session, scope, driver slot or queued request across a wait. Process pages
and the frame remain alive until synchronous unwind and thread reaping.

The writable-range helper extracts existing validated user-copy checks. It checks the
entire requested range, effective user/write permissions and overflow before I/O;
copy-out checks again before the first byte. Copies use validated physical aliases.
Nonzero EOF reads still require the whole writable destination. Zero reads check the
owned regular handle and READ, then ignore destination and binding. Length/offset
overflow and wrong record sizes return EINVAL. No unbounded or new 4 KiB stack buffer.

Stat/dirent staging initializes every byte and uses exact 64/272-byte little-endian
layouts. Directory EOF/errors copy nothing; no hidden cursor changes. A read failing
after a successful private prefix discards it. No asynchronous user copy or writable
filesystem operation was added.

Initial grants remain trusted, non-root and launch-specific. Owned tokens, independent
rights, attenuation, exact byte/case lookup, rejection of every `..`, absolute paths,
final/intermediate symlinks and root aliases remain in the common node layer. No Unicode
normalization/UTF-8 validation, uid bypass, global root, raw device or inode selector.
The disk graph still requires a trusted immutable provisioned namespace; handles and
parser validation do not authenticate malicious inode/block aliases.

Scopes retain the 200-tick, 512 logical-step, 256 backend-read and 1024 wait limits,
two tickets including debt and <=1 request/owner. Polling retains its independent
50,000,000-iteration production maximum. Tick progress is not a real-time guarantee.
Kill wins before user return; pending reads unwind before process file cleanup. IRQ
abandonment clears the driver owner, permitting session/thread/page reclamation while
only scalar ticket debt survives. Idle maintenance retires that debt without another
file call. Binding guards still include incarnation, epoch and reset sequence.
